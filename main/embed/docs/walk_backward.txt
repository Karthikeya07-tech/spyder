Twist backward walk, 30 s: motor angles
========================================

Source: the Android app (Twist-main/pathfindingsimulator, emotion_bundle.java, back()):
  the same 54-frame `frontx` table as the front walk, played in reverse (frame 53 -> 0),
  degrees = ticks*300/1023 (integer), plus the back() offsets
  [0, 0, -10, 0, +9, +10, 0, 0, -10, 0, 0, +10] for ID1..ID12.
  (Check: the same table with the front() offsets reproduces walk_forward_cycle.csv exactly.)
  60 knee values fell outside 0..300 deg (-10 / up to 310). The app sends those as invalid goals
  that the AX-12A ignores, so the knee stays at its limit; here they are clamped to 0 / 300.

Files
  walk_backward_cycle.csv   one cycle (54 frames) twice, app format: pass, frame, servo_1..servo_12
  walk_backward_deg.csv  time_s, ID1..ID12 servo degrees 0..300 (what play_action.py sends)
  walk_backward_ticks.csv / _rad.csv / .h   same rows as ticks / Gazebo radians / ESP32 header
